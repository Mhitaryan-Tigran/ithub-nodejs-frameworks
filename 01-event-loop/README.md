# Event Loop

```
node event_loop_demo.js
```

Полный вывод — в [output.txt](output.txt).

## Почему порядок именно такой

| Шаг | Что выводится | Где выполняется |
|---|---|---|
| 1 | `[1] … начало`, `[1] … конец`, `[async] Начало…`, `[async] Этот код выполнился ДО чтения файла` | Синхронный код в стеке вызовов. Таймеры, промисы и чтение файла только регистрируются |
| 2 | `[2] process.nextTick` | Очередь `nextTick` — выполняется сразу после текущей операции, раньше всех остальных очередей |
| 3 | `[3] Promise.then`, `[4] Promise.then chained` | Очередь микрозадач. Второй `then` встаёт в ту же очередь, когда выполнился первый, и выполняется до перехода к следующей фазе |
| 4 | `[5] setTimeout 0ms` | Фаза timers первого витка цикла. 0 мс фактически означает «не раньше 1 мс» |
| 5 | `[async] Файл прочитан…`, размер | Чтение идёт в пуле потоков libuv; колбэк попадает в фазу poll, когда операционная система вернула данные |
| 6 | `[6] setTimeout 100ms` | Фаза timers витка, на котором прошло 100 мс |

Совпадает с теорией: синхронный код → `process.nextTick` → микрозадачи (Promise) → макрозадачи по фазам цикла (timers → poll с вводом-выводом → …). Чтение файла может закончиться раньше или позже `setTimeout 0`, это зависит от скорости диска; на этом запуске оно заняло 0,42 мс и пришло после таймера 0 мс, но задолго до таймера 100 мс.
